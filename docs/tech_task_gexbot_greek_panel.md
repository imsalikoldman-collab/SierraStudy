# ТЗ: Графическое представление уровней (strike, specified_greek) в правой панели графика Sierra Chart

## Статус реализации (февраль 2026)
- Mode 1 (Positive Only) реализован в `projects/Wrapper/src/study.cpp`: линии строятся по `mini_contracts`, нормализуются по максимуму в видимом ценовом диапазоне, правый край выравнен справа с учётом `Panel Right Offset`. Минимальная длина линии — 4 px, чтобы слабые уровни не исчезали.
- Mode 2 (Negative & Positive) пока заглушка: Input доступен, но ничего не рисует и не падает.
- Панель вычисляет длину через пересчёт пикселей → бары по текущему масштабу X. Геометрия стабильна на скролле/зуме; при редких экстремальных отступах возможна небольшая погрешность длины — считаем допустимой.
- Добавлены отдельные линии ключевых уровней `major_short_gamma` (фиолетовый пунктир) и `major_long_gamma` (бирюзовый пунктир) с настройками включения/цвета/толщины/стиля.
- Добавлен переключатель слоя `Draw Layer` (Background/Foreground) для панельных и gamma-линий.
- Диагностический текст можно включать/выключать через `Show Diagnostics` (по умолчанию Off). Debug-лог по умолчанию всегда Off.

## 1. Цель
Реализовать отображение набора уровней, полученных из GEXBot (после обработки), на графике Sierra Chart в виде **горизонтальных линий** на ценовых уровнях `strike`. Длина линии должна быть **пропорциональна** значению `specified_greek` (с автонормализацией по видимому диапазону).

Предусмотреть **2 режима отображения**, выбираемых в настройках Study:
1) Показать **только положительные** значения `specified_greek` (реализуется сейчас).
2) Показать **все** значения (пока **заглушка**, без полноценной реализации).

---

## 2. Входные данные
### 2.1. Структура данных
Study получает вектор значений:
- `strike: double` — цена/страйк, на которой рисуется уровень.
- `specified_greek: double` — значение Greek на данном страйке (может быть отрицательным, нулевым, положительным).

Источник формирования вектора (парсинг/файл/внешний модуль) в рамках данного ТЗ не описывается — считаем, что к моменту отрисовки вектор доступен Study.

### 2.2. Допущения
- Значения `strike` могут быть не отсортированы.
- Возможны дубликаты `strike` (см. правила обработки ниже).
- Масштаб данных может меняться на каждом обновлении.

---

## 3. Режимы отображения
### 3.1. Mode = 1 (реальный): “Positive Only”
Отображаются только уровни, у которых:
- `specified_greek > 0`

### 3.2. Mode = 2 (заглушка): “Negative & Positive”
Пока полноценная логика не реализуется. Требуется временная заглушка:
- В настройках режим доступен для выбора.
- При выборе Mode=2 Study:
  - либо отображает в правой панели текст “MODE 2: TBD” (опционально),
  - либо не рисует ничего,
  - но **не падает**, не логирует ошибок “как критические”, не засоряет Chart Drawings.

---

## 4. Область отображения (правая панель)
Отрисовка выполняется на **выделенном участке справа** внутри области графика.

### 4.1. Геометрия панели
Панель задаётся настройками:
- `Panel Right Offset (px)` — отступ от правой границы области рисования графика.
- `Panel Width (px)` — ширина панели (максимальная длина линии при 100%).

Панель располагается так:
- `RightBoundaryX = RightEdgeOfChartDrawingArea - PanelRightOffset`
- `LeftBoundaryX  = RightBoundaryX - PanelWidth`

Важно: учитывать, что справа может располагаться шкала цены/поля. Правой границей панели считается **граница области рисования**, а не край окна приложения.

---

## 5. Правила отрисовки (Mode=1)
### 5.1. Какие уровни рисуются
Рисуются только уровни:
- `specified_greek > 0`
- `strike` попадает в **видимый ценовой диапазон** графика (по текущей шкале цен).
- Если в видимом диапазоне нет позитивных, рисуем все позитивные как фолбэк (чтобы линии не исчезали при узкой шкале).
- Дубликаты `strike` объединяются: берём максимальный `specified_greek` для данного страйка (дельта ~1e-9).

### 5.2. Вид линий
Линии горизонтальные на уровне `Y = strike`.

Параметры линии задаются в настройках:
- `Line Color`
- `Line Width`
- (Layer) `Draw Layer` — Background (под графиком) или Foreground (над графиком)
- Минимальная фактическая длина: 4 px, чтобы короткие линии были видны.

### 5.3. Длина линий и выравнивание
- Длина линии **пропорциональна** `specified_greek` относительно максимального положительного значения в видимом диапазоне (см. автомасштаб).
- **Правые концы** всех линий выровнены по `RightBoundaryX`.
- Левая точка линии вычисляется по длине:
  - `LineLengthPx = PanelWidth * (specified_greek / MaxGreekVisible)`
  - `X_end = RightBoundaryX`
  - `X_start = RightBoundaryX - LineLengthPx`
- Линия рисуется строго в пределах панели: `[LeftBoundaryX … RightBoundaryX]`.

---

## 6. Автомасштаб (Auto Scale)
### 6.1. Настройка
Переключатель убран из UI; **Auto Scale всегда включён**.

### 6.2. Логика Auto Scale
1) Определить **видимый ценовой диапазон** графика по текущей шкале (например, `VisibleLowPrice..VisibleHighPrice`).
2) Отобрать уровни Mode=1, попадающие в видимый диапазон и имеющие `specified_greek > 0`.
3) Найти:
   - `MaxGreekVisible = max(specified_greek)` среди отобранных.
4) Принять `MaxGreekVisible` за **100% длины** панели (`PanelWidth`).
5) Если `MaxGreekVisible <= 0` или нет уровней — **ничего не рисовать**.

---

## 7. Обновление/перерисовка
Study обязана перерисовывать линии в двух случаях:

1) **При поступлении новых значений** (вектор уровней обновился).
2) **При изменении масштаба по оси цен** (изменился видимый ценовой диапазон / price scale).

> Важно: при изменении масштаба по оси X (таймскейл/зум по времени) перерисовка не обязательна, если правая панель рассчитывается в пикселях и не зависит от количества баров.  
> Но изменение оси цен обязательно должно триггерить перерасчёт `MaxGreekVisible` и перерисовку.

### 7.1. Детектор изменения шкалы цен
Реализация должна хранить “последнее состояние” видимого диапазона цен:
- `LastVisibleLowPrice`
- `LastVisibleHighPrice`

Если текущие значения отличаются (с допуском), считаем, что шкала изменилась → перерисовать.

---

## 8. Обработка особых случаев
1) **Дубликаты strike**:
   - Базовое правило: рисовать **одну** линию на один `strike`.
   - Если встречаются несколько записей с одинаковым `strike`, использовать:
     - вариант A (предпочтительно): `specified_greek` = **max** среди положительных,
     - вариант B: суммирование (не делать сейчас без явного требования).
2) **Очень большие значения**:
   - Нормализация через `MaxGreekVisible` решает проблему.
3) **Нулевые/отрицательные**:
   - В Mode=1 игнорировать.
4) **strike вне видимого диапазона**:
   - Не рисовать.
5) **Панель слишком узкая/нулевая ширина**:
   - Если `PanelWidth <= 0` → не рисовать.

---

## 9. Настройки Study (Inputs)
Актуальные Inputs:
1) `Display Mode` — `Positive Only`, `Negative & Positive (TBD)`.
2) `Panel Width (px)` — ширина панели (дефолт 400).
3) `Panel Right Offset (px)` — отступ справа (дефолт 10).
4) `Line Color` — цвет панельных линий (дефолт бирюзовый `RGB(0,255,255)`).
5) `Line Width` — толщина панельных линий (дефолт 1).
6) `Draw Layer` — `Background`/`Foreground` для панельных и gamma-линий (дефолт Background).
7) `Show Diagnostics` — отображать/скрывать текстовый блок (дефолт No).
8) `Show Short Gamma` + `Color` + `Width` + `Style` — линия `major_short_gamma` (дефолты: On, `RGB(165,105,220)`, width 1, Dashed).
9) `Show Long Gamma` + `Color` + `Width` + `Style` — линия `major_long_gamma` (дефолты: On, `RGB(0,200,200)`, width 1, Dashed).

## 10. Критерии приёмки (Acceptance Criteria)
### 10.1. Mode=1
- На каждом `strike` с `specified_greek > 0` в видимом диапазоне рисуется горизонтальная линия.
- Правые концы линий выровнены по правой границе панели.
- Отношение длин линий соответствует отношению `specified_greek` после нормализации по `MaxGreekVisible`.
- При изменении масштаба цены (zoom/scale по оси Y) линии пересчитываются и перерисовываются.
- При обновлении вектора данных линии обновляются без артефактов (старые удаляются/обновляются корректно).

### 10.2. Mode=2
- Режим выбирается в настройках.
- При выборе не происходит ошибок/крашей.
- Реализована заглушка: либо ничего не рисуется, либо отображается простой маркер “TBD”.

### 10.3. Gamma key levels
- `major_short_gamma` и `major_long_gamma` рисуются горизонтальными линиями на своих ценах.
- Учитывают выбранный слой (Background/Foreground), цвет, толщину, стиль. По умолчанию включены, пунктир, толщина 1.
- При выключении соответствующего переключателя линия удаляется.

### 10.4. Diagnostics
- При `Show Diagnostics = No` текстовый блок отсутствует.
- При `Show Diagnostics = Yes` выводится текущий текст результата запроса/парсинга без дублей и утечек ChartDrawings.

---

## 11. Нефункциональные требования
- Перерисовка должна быть корректной и стабильной при частых обновлениях.
- Не должно происходить “захламление” графика тысячами Drawing объектов (предпочтительно — переиспользовать/adjust существующие, либо чистить предыдущие перед отрисовкой).
- Линии должны быть визуально стабильны при скролле/обновлении, без мерцания, насколько это возможно средствами Sierra Chart.

---

## 12. Примечания к реализации (ориентиры)
- Отрисовка выполняется как Chart Drawings (UseTool) или эквивалентным механизмом, позволяющим:

  - задавать X в пикселях/привязке к правой области,
  - обновлять существующие объекты, а не создавать бесконечно новые.
- Для детекта изменения шкалы цен — сравнение видимого диапазона (high/low).
- Для режима 2 пока оставить явный TODO/заглушку.

## Решённые проблемы и заметки для будущих доработок
- **Линии не появлялись**: добавлен фолбэк на все позитивные уровни, если в видимом диапазоне пусто; исправлена фильтрация по `ScaleRangeTop/Bottom` (учёт min/max).
- **Нулевые длины у малых значений**: введён минимум 4 px, чтобы короткие линии были видны.
- **Захламление графика**: перед каждой перерисовкой чистим старые панельные линии; key-level линии переиспользуют сохранённый LineNumber.
- **Слой отрисовки**: `Draw Layer` переключает `DrawUnderneathMainGraph`, решает перекрытие графиком.
- **Диагностика**: вывод текста теперь управляется `Show Diagnostics`; по умолчанию скрыт, чтобы не занимать экран.
- **Auto Scale**: зафиксирован в коде в состоянии ON, Input убран — снижает путаницу и предотвращает пустой вывод при ошибочном выключении.
- **Gamma key levels**: добавлены управляемые линии `major_short_gamma` / `major_long_gamma` с настраиваемым цветом/стилем/толщиной.
