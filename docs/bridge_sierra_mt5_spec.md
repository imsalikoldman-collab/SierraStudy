
# ТЗ: Логика моста Sierra Chart (ACSIL) → MT5 и формат сообщений

## 1. Назначение ACSIL-стадии

Одна специальная стадия (далее **Bridge-стадия**) работает на нужном графике и:

1. **Отслеживает состояние позиции по символу**  
   Через стандартные функции ACSIL можно получать позицию по символу (количество, направление, средняя цена).

2. **Отслеживает стоп-ордера по символу**  
   Для этого используется просмотр ордеров по символу (по индексу, символу и аккаунту).

3. **Формирует события по сделке** и записывает их в канал (named pipe) в виде строк JSON:
   - открытие (вход / стоп – в любой последовательности),
   - закрытие.

4. **Не сопровождает сделку после передачи**:  
   как только и вход, и стоп по конкретному `TradeID` отправлены в MT5, Bridge-стадия больше не передаёт изменения по этой сделке, а только один раз сообщает о её закрытии.

---

## 2. Ключевые понятия

- **Symbol** – символ инструмента, как в Sierra.
- **Позиция** – состояние по символу:
  - `flat` – позиции нет (количество = 0),
  - `long` – количество > 0,
  - `short` – количество < 0.
- **TradeID** – строковый уникальный идентификатор логической сделки в рамках моста.  
  Одинаковый `TradeID` связывает:
  - стартовый стоп (если он был первым),
  - вход,
  - финальный стоп (если он был вторым),
  - закрытие позиции.
- **Mode A – ENTRY_FIRST** – сначала вход, потом стоп.
- **Mode B – STOP_FIRST** – сначала стоп, потом вход.

---

## 3. Состояние, которое хранит Bridge-стадия

Для каждого символа / графика Bridge-стадия хранит:

1. **Состояние позиции:**
   - предыдущее направление (`flat/long/short`);
   - предыдущее количество;
   - последняя известная средняя цена.

2. **Текущий логический `TradeID` (если он активен):**
   - строка `TradeID`;
   - статус передачи:
     - «ничего не отправлено»,
     - «отправлен только вход»,
     - «отправлен только стоп»,
     - «отправлены вход и стоп» (**сделка передана в MT5**).

3. **Информация о стоп-ордере:**
   - факт наличия стопа, который считается связным с текущей сделкой;
   - его цена.

4. **Режим работы моста по этому графику:**
   - `ENTRY_FIRST` (Mode A) или `STOP_FIRST` (Mode B) – задаётся входом (Input) стадии.

---

## 4. Логика по шагам (ACSIL)

### 4.1. Отслеживание позиции

На каждом вызове Bridge-стадии:

1. Получить **текущее состояние позиции** по символу:
   - направление (`long/short/flat`),
   - количество,
   - средняя цена позиции.

2. Сравнить с предыдущим:

   **Событие входа:**
   - было `flat`, стало `long` или `short` → позиция **открыта**.

   **Событие выхода:**
   - было `long` или `short`, стало `flat` → позиция **закрыта**.

3. Обработка события входа:

   - Если **режим ENTRY_FIRST**:
     - сгенерировать новый `TradeID`;
     - отправить сообщение `OPEN_SIGNAL` (см. раздел 5);
     - отметить, что по этому `TradeID` «отправлен вход».

   - Если **режим STOP_FIRST**:
     - если до этого был отправлен `STOP_ONLY` и есть активный `TradeID`:
       - отправить `ENTRY_AFTER_STOP` с тем же `TradeID`;
       - отметить, что по этому `TradeID` «отправлены и вход, и стоп»;
     - если `STOP_ONLY` не было – по проектному решению:
       - либо работать как ENTRY_FIRST и отправить `OPEN_SIGNAL`,
       - либо игнорировать.

4. Обработка события выхода:

   - Если по символу есть активный `TradeID`, и его статус = «отправлены вход и стоп»:
     - отправить одно сообщение `CLOSE_SIGNAL` по этому `TradeID`;
     - очистить состояние по `TradeID` (сделка завершена).

---

### 4.2. Отслеживание стоп-ордеров

Параллельно Bridge-стадия просматривает ордера по символу и ищет **актуальный стоп-ордер** (в базовом варианте – первый найденный подходящий стоп):

1. Определить:
   - есть ли стоп-ордер по символу;
   - его цену;
   - сравнить с состоянием прошлого вызова.

2. Сценарии:

#### a) Стоп появился, раньше стопа не было

- Если статус `TradeID` ещё не установлен:

  - Если позиция **flat** и режим **STOP_FIRST**:
    - сгенерировать новый `TradeID`;
    - по цене стопа и текущей цене определить направление:
      - стоп ниже рынка → предполагаемый `LONG`,
      - стоп выше рынка → предполагаемый `SHORT`;
    - отправить сообщение `STOP_ONLY` (стартовый стоп без позиции);
    - отметить, что по этому `TradeID` «отправлен стоп».

  - Если позиция уже **long/short** (режим ENTRY_FIRST):
    - если по позиции ещё не создавался `TradeID`, создать его;
    - отправить `STOP_LEVEL` (стоп для уже открытой позиции);
    - отметить, что по этому `TradeID` «отправлены вход и стоп» (если вход уже был).

#### b) Стоп исчез

- В текущем проекте можно **не слать отдельное сообщение**, а только сбрасывать локальное состояние стопа.
- Ответственность за дальнейшую защиту – на стороне MT5.

#### c) Стоп изменился по цене

- Если по `TradeID` **ещё не передана пара «вход + стоп»**, поведение определяется проектно:
  - можно повторно отправлять обновлённый стоп (как новый `STOP_ONLY` / `STOP_LEVEL`),
  - либо игнорировать и считать, что MT5 работает по первому уровню.

- Если по `TradeID` уже **отправлены и вход, и стоп** (сделка передана в MT5):
  - любые изменения стопа в Sierra **игнорируются**;
  - дополнительных сообщений по стопам не формируется.

---

### 4.3. Условие «сделка передана в MT5»

Для каждого `TradeID` Bridge-стадия ведёт две отметки:

- «отправлен вход»,
- «отправлен стоп».

**Как только обе отметки стали истинными:**

- статус `TradeID` = «передан в MT5»;
- стадия:
  - больше не отправляет по этому `TradeID` сообщений `OPEN_SIGNAL`, `ENTRY_AFTER_STOP`, `STOP_ONLY`, `STOP_LEVEL` или `STOP_UPDATE`;
  - продолжает только отслеживать момент закрытия позиции и при первом переходе в `flat` отправляет `CLOSE_SIGNAL`.

---

## 5. Формат сообщений в канал (named pipe)

### 5.1. Общие требования

1. Используется один именованный канал (например, `\\.\pipe\SierraToMT5`), открытый на запись.
2. Каждое сообщение – одна строка JSON, оканчивающаяся переводом строки (`\n`).
3. Кодировка – UTF‑8.
4. Принимающая сторона читает по строкам и парсит JSON.

### 5.2. Общие поля JSON

Во всех сообщениях используются следующие поля:

- `type` – тип сообщения, одно из:
  - `"OPEN_SIGNAL"`,
  - `"STOP_ONLY"`,
  - `"ENTRY_AFTER_STOP"`,
  - `"STOP_LEVEL"`,
  - `"CLOSE_SIGNAL"`.

- `trade_id` – строка, уникальный идентификатор сделки.

- `symbol` – строка, символ инструмента в формате Sierra.

- `direction` – `"LONG"` или `"SHORT"` (там, где применимо).

- `ts_ms` – целое число: метка времени события в миллисекундах (UTC или выбранное единообразное время).

- `source` – строка `"sierra"`.

### 5.3. Типы сообщений

#### 1) `STOP_ONLY` – сценарий «сначала стоп» (Mode B, шаг 1)

Отправляется, когда:

- позиция по символу `flat`,
- поставлен первый стоп-ордер (режим `STOP_FIRST`),
- инициируется потенциальная сделка.

Дополнительные поля:

- `stop_price` – цена стопа;
- `mode` – строка `"STOP_FIRST"`.

**Назначение:** MT5 должен запомнить направление сделки и уровень стопа, вход будет передан позже.

---

#### 2) `ENTRY_AFTER_STOP` – вход после стопа (Mode B, шаг 2)

Отправляется, когда:

- по этому `trade_id` ранее был отправлен `STOP_ONLY`,
- позиция по символу стала long или short.

Дополнительные поля:

- `entry_price` – средняя цена входа в позицию по данным Sierra.

**Назначение:** MT5 по этому сообщению понимает, что по заранее объявленной сделке произошёл вход, и, имея стоп, может рассчитать размер позиции и открыть её у брокера.

После отправки `ENTRY_AFTER_STOP` при наличии `STOP_ONLY` статус `TradeID` становится «передан в MT5».

---

#### 3) `OPEN_SIGNAL` – сначала вход (Mode A, шаг 1)

Отправляется, когда:

- позиция была `flat`,
- стала `long` или `short`,
- режим моста `ENTRY_FIRST`.

Дополнительные поля:

- `entry_price` – средняя цена входа.

**Назначение:** MT5 получает информацию о факте открытия позиции и её цене. Уровень стопа будет передан отдельным сообщением `STOP_LEVEL`.

---

#### 4) `STOP_LEVEL` – стоп для уже открытой позиции (Mode A, шаг 2)

Отправляется, когда:

- позиция уже открыта (есть `TradeID` с отправленным `OPEN_SIGNAL`),
- появляется первый стоп-ордер.

Дополнительные поля:

- `stop_price` – цена стопа;
- `mode` – строка `"ENTRY_FIRST"`.

**Назначение:** завершает передачу параметров сделки в MT5: теперь есть и вход, и стоп. MT5 может рассчитать риск и зафиксировать объём.

После отправки `STOP_LEVEL` при уже отправленном `OPEN_SIGNAL` статус `TradeID` становится «передан в MT5».

---

#### 5) `CLOSE_SIGNAL` – закрытие позиции

Отправляется один раз, когда:

- по `TradeID` статус = «передан в MT5»,
- позиция по символу переходит из `long/short` в `flat`.

Дополнительные поля:

- `close_reason` – текстовая причина закрытия:
  - `"signal"` – по торговому сигналу,
  - `"manual"` – вручную,
  - `"flatten"` – общий Flatten и т.п.;
- `close_price` – цена закрытия позиции по данным Sierra.

**Назначение:** MT5 должен закрыть позицию по этому `TradeID` у брокера (как правило, по рынку) и завершить сопровождение сделки.

После отправки `CLOSE_SIGNAL` Bridge-стадия очищает внутреннее состояние по данному `TradeID`.

---

## 6. Ограничения и договорённости

1. После того как по `TradeID` отправлены и вход, и стоп, Bridge-стадия **не сопровождает** сделку:
   - не передаёт переносы стопа,
   - не учитывает доливки и частичные выходы.
   Всё сопровождение находится на стороне MT5.

2. В базовой реализации предполагается **не более одной активной логической сделки на символ**.  
   Для поддержки нескольких одновременных сделок по одному символу потребуется расширение логики хранения нескольких `TradeID` на символ.

3. Отказ брокера в открытии/закрытии позиции, а также глобальные защитные стопы по счёту обрабатываются на стороне MT5 и в этом ТЗ не описываются.
